# SeekerStudio: Technical Blueprint & System Specification

## 1. Product Vision & Executive Summary

This document serves as the complete technical blueprint for building a **browser-based "Vibe Coding" IDE specifically designed for the Solana Mobile ecosystem (Seeker & Solana Mobile Stack)**.

### Core Value Proposition
- **Zero-Friction Setup**: Eliminates hours of setting up Android Studio, NDK, Java, Solana Mobile Wallet Adapter (MWA) bridges, and local test validators. Developers or non-technical founders can build, test, and preview native Solana Android apps in seconds.
- **Instant Live Native Preview**: Utilizes **Redroid (Remote Android in Docker)** streamed via **ws-scrcpy (H.264 over WebSocket)** directly to an in-browser HTML5 `<canvas>`.
- **AI-Powered Code Generation**: Incorporates tight system prompts and self-healing agent loops tuned specifically for React Native (`@solana/web3.js` and `@solana-mobile/mobile-wallet-adapter-protocol-web3js`).
- **Cost-Protected Freemium**: Session-level compute gating (idle pause, warm container pool, metered overage) protects server margins while enabling viral adoption.

## 2. Business & Monetization Architecture: Freemium

To protect server GPU/RAM margins while ensuring rapid viral adoption within the Solana developer community, the system enforces a strict **Freemium Gating Model** with **bundled compute minutes** and **metered overage**.

### Plan Breakdown

| Feature / Resource | Free Tier (Hook) | Pro Developer Tier ($59/mo) |
| :--- | :--- | :--- |
| **Active Projects** | 1 Project Max | Unlimited Projects |
| **AI Generation Prompts** | 20 Prompts / month | 500 Prompts / month (smart model routing) |
| **Emulator Device Minutes** | 60 min / month | 1,500 min / month (~25h) |
| **Native Redroid Emulator** | 5-minute continuous preview, 30 FPS guest rendering (Auto-pause on idle) | 60 FPS hardware-encoded continuous streamed session |
| **Solana Network Support** | Devnet / Localhost only | Devnet, Testnet & Mainnet-Beta RPCs |
| **APK Build & Export** | Locked | Unlimited Signed APK Downloads |
| **Solana dApp Store Bundle** | Excluded | 1-Click Manifest & Packaging (`dapp-store-manifest.json`) |
| **Overage** | — | $0.02 / device-minute, $0.01 / prompt |

### Cost Protection & Margin Model
- **AI Token Routing**: ~80% of routine generations are routed to a cheap flash-tier model; Claude (Sonnet-class) is reserved for complex rewrites. A worst-case 500-prompt Pro month targets **$25–40 AI + ~$10 infra**, comfortably inside the $59 price point.
- **Bundled + Metered**: Predictable subscription (compute minutes + prompt budget) with metered overage that absorbs power users instead of letting them saturate margins.
- **Burn-Rate Dashboard**: Per-user tracking of AI spend and active host-minutes to inform future price changes.

### Session Management & Cost Protection Logic
1. **Idle Container Pause**: If no user interaction (touch/key event or code prompt) is detected for **5 minutes**, the background Redroid container is paused (`docker pause`).
2. **Session Termination**: At 15 minutes of inactivity, the container is destroyed, and the user's project state is saved to persistent storage (`/data/workspaces/<user_id>/<project_id>`).
3. **Warm Paused Pool**: Each host keeps 3–5 pre-booted, `docker pause`d containers. Re-connection on the Free tier calls "Resume Container" and **unpauses in ~2 seconds** (cold start ~20–30s with a loading state).
4. **Metering**: Active device-minutes and prompt usage are recorded per user and enforced against tier limits with metered overage.

## 4. Technology Stack Specification

- **Frontend**: Next.js (App Router), TypeScript, Tailwind CSS, `@monaco-editor/react`, `@xterm/xterm` (web terminal), `ws-scrcpy` JS client (`WebCodecs` / `MsePlayer` / `TinyH264Player`).
- **AI Backend / Orchestrator**: **Go 1.23+**
  - HTTP: stdlib `net/http` (1.22+ method routing) + `github.com/go-chi/chi/v5`.
  - WebSockets: `github.com/gorilla/websocket` (frontend session sockets).
  - AI: `github.com/anthropics/anthropic-sdk-go` with **model routing** (flash-tier for routine generation, Sonnet-class for complex rewrites).
  - File watching: `github.com/fsnotify/fsnotify` (replaces chokidar) to trigger Metro hot-reload events.
  - Docker: `github.com/docker/docker` client SDK (container lifecycle, warm pool, exec).
  - Billing: `github.com/stripe/stripe-go/v8` (subscriptions + metered overage).
  - SQLite / Postgres driver for user/tier/metering records.
- **Streaming Gateway**: Go API server terminates the user-facing WebSocket, authenticates the session, and proxies to a per-user **ws-scrcpy** daemon instance (which bridges ADB/scrcpy). H.264 frames are decoded client-side via WebCodecs (hardware) with MSE/TinyH264 fallbacks.
- **Runtime & Emulator Environment**:
  - Host OS: Ubuntu 24.04 LTS (dedicated hosts) or WSL2 locally, with `binder_linux` loaded.
  - Container: `redroid/redroid:14.0.0_64only-latest`.
  - Android Bridge: ADB over TCP (Port 5555), `ws-scrcpy`.
  - App Stack: React Native 0.74+, Expo (Bare workflow), `@solana/web3.js`, `@solana-mobile/mobile-wallet-adapter-protocol-web3js`.
  - Wallet: official `solana-mobile/mock-mwa-wallet` APK baked into the image.
  - Local chain: `solana-test-validator` inside the container for pre-funded devnet simulation.

### Go Service Layout
```
cmd/server/main.go
internal/auth/            # session tokens, tier resolution
internal/billing/         # device-minute + prompt metering, Stripe
internal/container/       # Docker lifecycle, warm paused pool
internal/orchestrator/    # AI pipeline, self-healing loop, vision check
internal/prompts/         # system prompts as Go constants
internal/streaming/       # authenticated ws-scrcpy proxy
internal/terminal/        # authenticated web terminal (PTY ↔ adb shell / docker exec)
internal/store/           # users, projects, usage records
internal/workspace/       # project volume mount / snapshot
```

## 5. Implementation Roadmap & Step-by-Step Instructions

When implementing this repository, follow this execution sequence in order:

### Phase 1: Host & Redroid Docker Setup
1. **Enable Android IPC Drivers on Host System**:
   ```bash
   sudo apt update && sudo apt install -y linux-modules-extra-$(uname -r)
   sudo modprobe binder_linux devices="binder,hwbinder,vndbinder"
   echo 'binder_linux options binder_linux devices="binder,hwbinder,vndbinder"' | sudo tee -a /etc/modules-load.d/redroid.conf
   ```
2. **Verify kernel capability before deploy** (gate hosts that lack the modules):
   ```bash
   grep binder /proc/filesystems   # must list binderfs
   ```
   On dedicated hosts, pin the kernel version; if the stock kernel lacks the modules, build them via `remote-android/redroid-modules` (DKMS).
3. **Launch Redroid Base Image**:
   ```bash
   docker run -d --name redroid-seeker-base --privileged -p 5555:5555 \
     redroid/redroid:14.0.0_64only-latest \
     androidboot.redroid_width=1080 \
     androidboot.redroid_height=2400 \
     androidboot.redroid_dpi=420 \
     androidboot.redroid_fps=60
   ```
4. **Install Pre-baked Solana Dev Stack**:
   - Connect ADB: `adb connect localhost:5555`
   - Bake the official `mock-mwa-wallet` APK into the image (configured with a known devnet keypair via `local.properties`).
   - Set a **device PIN programmatically** on first boot (MWA requires device authentication).
   - Run `solana-test-validator` inside the container for pre-funded balances with no faucet limits.
   - Add a "Reset / Fund wallet" action in the UI calling the validator's airdrop.

### Phase 2: AI Prompt System & Orchestration Engine (Go)
Create a dedicated prompt module `internal/prompts/prompts.go` with strict guardrails for Solana Mobile:

```go
package prompts

const SolanaMobileSystemPrompt = `
You are an expert React Native engineer specializing in Solana Mobile Stack (SMS) dApps for the Solana Seeker device.
Target Screen Resolution: 1080x2400 (Aspect ratio 20:9).

STRICT CODE GENERATION RULES:
1. Use React Native functional components with TypeScript.
2. For Solana wallet connections, ALWAYS use:
   import { transact } from '@solana-mobile/mobile-wallet-adapter-protocol-web3js';
   import { Connection, PublicKey, clusterApiUrl } from '@solana/web3.js';
3. Wrap all wallet requests inside the MWA 'transact' callback.
4. Ensure UI elements are touch-friendly and fit within Seeker's display boundaries.
5. Never introduce unverified third-party native C++ dependencies. Stick to standard Expo/React Native components and @solana/web3.js.
6. Structure every file with named default exports so Fast Refresh works reliably.
7. Wrap the app root in a dev-only <ErrorBoundary> that renders error text on screen.
`
```

Implement the file write & self-healing pipeline in `internal/orchestrator/orchestrator.go`:

1. **Capture prompt** (from authenticated WebSocket or REST).
2. **Plan + patch**: Query the Anthropic API with the current project tree; the model returns a structured JSON patch, not freeform file writes.
3. **Typecheck gate**: Run `tsc --noEmit` on the patched files **before** writing to disk — reject and retry cheaply on compile errors.
4. **Write**: Apply the validated patch to the mounted container volume (`/data/workspaces/<user_id>/src`); `fsnotify`/Metro pushes Fast Refresh to the running Redroid app without restarting the Android container.
5. **Verify**: Tail `adb logcat` (`ReactNativeJS:E`, `AndroidRuntime:E`) and capture `adb exec-out screencap -p`; on error, send message + stack + failing file + tree back to the heal LLM (max 3 attempts, watchdog-timed).
6. **Vision check**: Feed the post-bundle screenshot to a vision model to confirm the UI matches intent.

### Phase 3: H.264 Screen Streaming (ws-scrcpy)
- The Go backend terminates the user-facing WebSocket with **per-session bearer-token auth** (WSS required; ws-scrcpy ships unencrypted/unauthenticated by default) and proxies to the per-user `ws-scrcpy` daemon.
- Render the stream in the Web UI inside a custom `<canvas>`/`<video>` container:
  ```tsx
  // Canvas Component Preview
  <div className="relative w-[360px] h-[800px] border-8 border-slate-900 rounded-[36px] overflow-hidden shadow-2xl">
    <canvas id="seeker-emulator-stream" className="w-full h-full object-cover" />
  </div>
  ```
- Use ws-scrcpy's built-in input pipeline (touch, keyboard, clipboard, multi-touch) wired via its `postMessage` protocol to the canvas — no hand-rolled ADB touch serialization. Player priority: WebCodecs → MSE → TinyH264.
- **Web terminal**: `xterm.js` panel in the IDE connects over an authenticated WebSocket to the Go terminal proxy (`internal/terminal`), which attaches a PTY to `adb shell` (or `docker exec` into the container) for running `adb`/`solana`/Metro/Gradle commands. Enable ws-scrcpy's `INCLUDE_ADB_SHELL` as a fallback.

### Phase 4: Freemium Enforcement & Session Manager (Go)
Implement container state management in `internal/container/manager.go`:

- Track user tier (`FREE` vs `PRO`).
- Maintain the **warm paused pool**; resume = `docker unpause`, cold = mount project volume into a fresh container.
- Set an active timer on touch/code activity. If user is `FREE` and idle > 5 minutes:
  - Run `docker pause redroid-user-<id>`.
  - Update UI state to show an overlay: `"Session Paused to Save GPU Resources. Click to Resume."`
- Meter device-minutes and prompts against tier budgets in `internal/billing/`; trigger overage for Pro via Stripe.
- Restrict APK Export API routes: check the user DB record for `is_pro === true` before running `cd android && ./gradlew assembleRelease`.
